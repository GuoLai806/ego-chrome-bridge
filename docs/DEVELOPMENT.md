# 开发记录与复现依据

## 路线与来源

2026-10-21。先研究现成开源接入，不自行重写浏览器。旧npm社区桥携带1.2.5指南，与当前2.1不一致，未用于本轮正式任务。选用 [PR291](https://github.com/citrolabs/ego-lite/pull/291) 的当前SDK宿主，固定 `7bb1545912bf7e7bdf4239a321d36af0e68cb65c`。

最初原样Mac探针真实失败：native bindings未安装，提示listTaskSpaces缺失。原因是社区平台入口只启用Linux。第一阶段只补macOS显式启用和Linux专用Ozone参数条件，独立Chrome下随后跑通30题、KS、B站。没有改SDK快照/动作算法。

但独立Chrome不继承日常登录状态，不能冒充用户要求的日常Chrome。因此第二阶段临时启用Chrome官方会话调试，参考Google官方发现机制，增加WebSocket→现有CDP接口的薄运输层，并将隔离context归属换为本轮目标ID归属。完整改动相对PR291为7文件119行插入、21行删除，含2个新增测试；来源快照 `6888f9a`。

日常模式先做空白连接探针：只暴露本轮about:blank，关闭后Chrome继续运行。离线回归最初发现接管状态下聚焦查询误用了agent权限检查；修复后554项通过。之后同一二进制、同一DS配置，从新交互会话逐项执行三个正式任务。详细耗时与局限见 [实测记录](../test-results/README.md)。模块测试不是业务任务的替代。

## 本仓库如何整理

只从已提交的Ego源码快照导出，未复制原工作目录的未跟踪文件、node_modules或私有资料。完整上游根目录嵌在 `vendor/ego-lite/`，保留其许可证、构建需要的skill、测试夹具和文档；其中.github不在本仓库根，不能触发旧发布流水线。

根目录的 `bin/ego-browser` 是新增的发行接线：固定本地SDK、私有状态目录和日常Chrome模式，支持stdin、脚本文件及指南中的-e。skill保留匹配的API正文，但用日常模式说明替换旧Linux隔离模式前言，避免错误告诉Agent“Cookie隔离/不继承登录”。打包检查曾捕获这一前言矛盾，修正后重跑。它不启动Agent、不调用模型、不执行第二决策循环。这个新包装完成打包/离线检查，不把此前通过旧测试包装的三任务成绩伪装成它的新一轮业务实测。

## 维护方式

1. 固定来源SHA，先保存可回退快照；不要直接跟随上游main漂移。
2. 先用真实任务定位，再最小修改通用运输/观察/动作模块；站点脚本不要塞进底层。
3. 记录是否已投递、新观察、任务最终结果；不要因非必要截图失败而拦住正常控件任务。
4. 修改vendor源码后在其package中build、typecheck、跑完整测试；必要时再做明确范围的实机任务。变更后的源码不能冒用旧二进制的业务成绩。
5. 多Agent整合放在工具之外；本库只解决浏览器工具，不重新长出Pi或一套Agent框架。

## 目前最值得做的下一步

- 优先修非默认网站缩放下的截图坐标/DPR/像素舍入，覆盖页面顶部和深滚动；不做KS专用补丁。
- 让调用者用现有AX快照/截图补充普通DOM漏读的Shadow DOM内容，不引入第二模型。
- 用空状态、回复层级和滚动是否有进展来结束等待，避免“必须两条主评论”等僵化规则。
- 需要跨iframe、多个Profile、其他桌面系统时，分别补实测证据，不能从当前样本推导全部兼容。

这些是后续建议，不是本仓库已经完成的能力。可接受任务中一两步出错后自主恢复；验收看任务结果，不以零错误为前提。
